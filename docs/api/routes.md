# Маршрутизация Runtracker API

**Статус:** Проект (согласованная целевая схема, не все маршруты реализованы)  
**Дата:** 2026-11-02  
**Основание:** [ADR-0001 — Базовые модели предметной области](../adr/0001-domain-model.md)

## Дерево маршрутов

```text
/v1
├── /healthcheck
├── /profile
├── /workouts
│   ├── /{id}
│   └── /{id}/clone
├── /scheduled-workouts
│   └── /{id}
└── /activities
    └── /{id}
```

## Таблица маршрутов

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/v1/healthcheck` | Проверка доступности приложения |
| `GET` | `/v1/profile` | Получить физиологический профиль |
| `PATCH` | `/v1/profile` | Обновить физиологический профиль |
| `GET` | `/v1/workouts` | Список тренировок |
| `POST` | `/v1/workouts` | Создать тренировку |
| `GET` | `/v1/workouts/{id}` | Получить тренировку |
| `PATCH` | `/v1/workouts/{id}` | Обновить тренировку |
| `DELETE` | `/v1/workouts/{id}` | Удалить тренировку и её назначения |
| `POST` | `/v1/workouts/{id}/clone` | Клонировать тренировку |
| `GET` | `/v1/scheduled-workouts` | Получить назначения тренировок |
| `POST` | `/v1/scheduled-workouts` | Назначить тренировку |
| `GET` | `/v1/scheduled-workouts/{id}` | Получить назначение |
| `PATCH` | `/v1/scheduled-workouts/{id}` | Изменить назначение |
| `DELETE` | `/v1/scheduled-workouts/{id}` | Удалить назначение |
| `GET` | `/v1/activities` | Получить фактические активности |
| `POST` | `/v1/activities` | Создать фактическую активность |
| `GET` | `/v1/activities/{id}` | Получить активность |
| `PATCH` | `/v1/activities/{id}` | Изменить активность |
| `DELETE` | `/v1/activities/{id}` | Удалить активность |

## Правила

1. Приложение пока однопользовательское и использует SQLite. Отдельный API управления `User` не требуется; `/v1/profile` относится к единственному спортсмену.
2. `Workout` переиспользуется: изменения применяются ко всем связанным `ScheduledWorkout`. Назначение не содержит снимка характеристик тренировки.
3. `POST /v1/workouts/{id}/clone` создаёт независимый `Workout` с новым идентификатором.
4. `DELETE /v1/workouts/{id}` физически удаляет тренировку и каскадно все её назначения, включая прошедшие.
5. Удаление назначения не удаляет `Activity`; связь с назначением снимается, фактические данные сохраняются.
6. Успешное удаление возвращает `204 No Content`.
7. `Activity` может существовать без назначения. Тип активности определяется через `ActivityType`, без отдельных маршрутов для каждого вида спорта.
8. Для списков назначений и активностей предполагаются фильтры дат: `?from=YYYY-MM-DD&to=YYYY-MM-DD`. Для активностей также предполагается фильтр `?type=running`. Форматы и правила фильтрации предстоит уточнить при реализации.
9. Это планируемые маршруты, а не обязательный объём MVP. Маршруты реализуются по мере появления сценариев использования.
